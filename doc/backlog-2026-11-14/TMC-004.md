## TMC-004 · Verify PostgreSQL migrations and core constraints

**Type:** BUILD · **Feature:** foundation · **Priority:** P0 · **Area:** devops

**Parent:** [TMC-101](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/107)
**Dependencies:** [TMC-003](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/3)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
ORM entities/registry/migration đã có. Kiểm chứng constraints và bổ sung migration cho gap thật trên DB test được chỉ định; không reset DB hiện tại.

### Scope / Implementation checklist
- [ ] Viết manifest 37 bảng, mapping property/type, PK/UK/FK và tách vòng tham chiếu bằng ALTER TABLE.
- [ ] Thêm partial UNIQUE station/event, OPEN/attempt, redemption, sourceId và FK deferred ledger/correction.
- [ ] Triển khai TypeORM UnitOfWork, transaction context riêng và repository dùng đúng transactional manager.
- [ ] Tạo PostgreSQL dev/test riêng, synchronize:false, env mẫu và migration run/revert trên DB tạm.

### Acceptance criteria
- [ ] AC1: Migration chạy từ DB rỗng; mọi FK có bảng/khóa đích đúng kiểu.
- [ ] AC2: Insert Event+revision 1 commit được; thiếu revision và vi phạm unique bị chặn.
- [ ] AC3: Rollback UnitOfWork không để audit/command/attendance lưu một phần.

### Verification plan
- [ ] Chạy migration trên PostgreSQL test rỗng; so catalog với 37 bảng schema.
- [ ] Thử vi phạm PK/FK/UK/partial unique và deferred head.
- [ ] Thử hai transaction song song và lỗi giữa transaction; không dùng SQLite thay tính năng PG.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/platform/infrastructure/database/migrations`, `api/src/platform/infrastructure/database/entities.ts`, `api/src/modules`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
