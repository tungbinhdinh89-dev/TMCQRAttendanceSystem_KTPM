## TMC-034 · Write the implementation-based SOLID reflection

**Type:** DOCS · **Feature:** architecture · **Priority:** P0 · **Area:** architecture

**Dependencies:** [TMC-033](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/33), [TMC-030](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/30)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Viết reflection ngắn theo M2 về lợi ích, khó khăn, modularity, maintainability và extensibility, dựa trên code/review/rework đã xảy ra.

### Scope / Implementation checklist
- [ ] Chọn ít nhất hai tình huống thực tế như thay gateway hoặc lỗi transaction context.
- [ ] Mô tả trước/sau và nguyên tắc giúp giải quyết; nêu chi phí abstraction/DI.
- [ ] Liên kết ví dụ033 và kết quả030, ghi rõ giới hạn/chưa làm.
- [ ] Viết bằng giọng phản ánh của nhóm, Solo Developer kiểm tra tính xác thực trước nộp.

### Acceptance criteria
- [ ] AC1: Trả lời đầy đủ lợi ích, khó khăn và ảnh hưởng SOLID theo đề.
- [ ] AC2: Không bịa kinh nghiệm, số liệu hoặc test chưa chạy.
- [ ] AC3: Nội dung nhất quán với code và architecture cuối cùng.

### Verification plan
- [ ] Cross-review reflection với issue/review log và evidence thực tế.
- [ ] Kiểm tra trích dẫn code/diagram còn đúng.
- [ ] So yêu cầu reflection ở PDF M2 trang3.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules`, `api/test`, `report/sections/content.tex`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
