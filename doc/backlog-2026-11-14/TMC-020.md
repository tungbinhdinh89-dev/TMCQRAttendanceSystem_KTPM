## TMC-020 · Expose scoped attempt status and attendance history

**Type:** FEATURE · **Feature:** attendance · **Priority:** P0 · **Area:** backend

**Parent:** [TMC-094](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/100)
**Dependencies:** [TMC-019](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/19), [TMC-007](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/7)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Tạo read models/DTO nhỏ cho status, access history và attendance history. Không cung cấp getDatabase tổng hợp toàn bộ dữ liệu như prototype.

### Scope / Implementation checklist
- [ ] Tạo lookup theo eventId cho chính trạm hoặc user đủ quyền.
- [ ] Tạo history/detail có pagination, filter thời gian, station/factory và predicate scope ở query.
- [ ] Trả command/evidence/current revision và correlationId; redaction thông tin cá nhân theo actor.
- [ ] Đặt giới hạn page size/range và index query cần dùng; bỏ voided khỏi report hiệu lực theo policy.

### Acceptance criteria
- [ ] AC1: EMP chỉ đọc self, SEC đúng factory, SUP đúng team, EXE chỉ aggregate.
- [ ] AC2: Không truy cập chéo bằng đoán UUID hoặc sửa query filter.
- [ ] AC3: Retry lookup sau QR hết hạn vẫn đọc kết quả request đã nhận.

### Verification plan
- [ ] API tests 401/403/404 policy và IDOR đa factory.
- [ ] Pagination/filter ổn định khi nhiều event cùng timestamp.
- [ ] Query plan cơ bản và contract response không chứa QR/session/secret.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/att`, `api/src/modules/gate`, `client/src/features/employee-mobile/Mobile.tsx`, `contracts/src/attendance.ts`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
