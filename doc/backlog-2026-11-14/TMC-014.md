## TMC-014 · Persist idempotent attempts before gate dispatch

**Type:** FEATURE · **Feature:** gate-processing · **Priority:** P0 · **Area:** backend

**Parent:** [TMC-093](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/99)
**Dependencies:** [TMC-004](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/4), [TMC-011](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/11), [TMC-012](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/12), [TMC-013](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/13)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Tạo transaction chuẩn bị bền vững trước HTTP tới TCS. Duplicate lookup xảy ra trước replay redemption; requestHash bỏ trường thay đổi theo lần retry.

### Scope / Implementation checklist
- [ ] Chuẩn hóa request và hash; tìm UNIQUE(stationId,eventId) trước xác thực token lại của request cũ đã tiếp nhận.
- [ ] Cùng ID/hash trả trạng thái cũ, cùng ID khác hash trả 409; station khác không đọc được request.
- [ ] Trong một UnitOfWork lưu AccessAttempt, PREPARED OPEN, audit và hook redemption cho ticket 015.
- [ ] Đảm bảo lỗi persistence dừng trước gateway; lưu denied attempts có reason và không command OPEN.

### Acceptance criteria
- [ ] AC1: Hai POST đồng thời cùng station/event tạo đúng một attempt và một OPEN cơ sở.
- [ ] AC2: Payload khác cùng ID trả 409, không đổi dữ liệu đã lưu.
- [ ] AC3: DB unavailable/rollback không có physical OPEN.

### Verification plan
- [ ] Integration race cùng key và collision khác payload.
- [ ] Test duplicate sau token hết hạn trả trạng thái đã có, không tạo request mới.
- [ ] Inject DB fault trước commit, so mock gateway execution counter=0.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/gate`, `api/src/modules/att`, `api/src/platform/application`, `contracts/src/attendance.ts`; kiểm tra đường dẫn thực tế khi nhận việc.
