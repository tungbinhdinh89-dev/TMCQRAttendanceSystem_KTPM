## TMC-017 · Display server-issued QR codes in the employee portal

**Type:** UI · **Feature:** qr · **Priority:** P0 · **Area:** frontend

**Parent:** [TMC-091](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/97)
**Dependencies:** [TMC-010](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/10), [TMC-008](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/8)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Tái sử dụng trang mobile hiện có, thay makeQr phía client bằng endpoint self. UI chỉ trình bày QR, không giữ signing key hay quyết định quyền.

### Scope / Implementation checklist
- [ ] Hiển thị token server bằng QR component hiện hữu, countdown từ expiresAt/serverTime.
- [ ] Refresh có loading/error, hạn chế request; hết hạn/thu hồi không hiển thị như mã còn dùng.
- [ ] Xóa payload khi logout/đổi user; không đưa QR vào localStorage journal hoặc telemetry.
- [ ] Giữ layout/tokens Figma và kiểm tra mobile 360px, light/dark.

### Acceptance criteria
- [ ] AC1: Token UI được server validator chấp nhận, không còn tự sinh tmc-access:v1 cho server mode.
- [ ] AC2: Mất mạng cấp mã báo lỗi, không gia hạn QR cũ ở client.
- [ ] AC3: EMP không chọn employeeId khác để phát QR.

### Verification plan
- [ ] Manual QR countdown/refresh bằng API clock fixture.
- [ ] Test logout/đổi tài khoản không giữ mã cũ.
- [ ] Responsive/contrast và lỗi 401/expired/revoked.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `client/src/features/employee-mobile/Mobile.tsx`, `client/src/lib/qr.ts`, `client/src/data/auth.ts`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
