## TMC-012 · Evaluate access policies using server-owned data

**Type:** FEATURE · **Feature:** gate-processing · **Priority:** P0 · **Area:** backend

**Parent:** [TMC-093](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/99)
**Dependencies:** [TMC-006](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/6), [TMC-011](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/11)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
AccessPolicy thuần kiểm tra grant tách khỏi phân công tổ chức. Quyền EXIT theo chính sách baseline; phần mềm không thay cơ chế thoát hiểm.

### Scope / Implementation checklist
- [ ] Lấy station/factory/direction từ station credential và cấu hình server.
- [ ] Kiểm tra station active, employee active, credential hợp lệ và access grant [from,to).
- [ ] Ghi typed ALLOW/DENIED reason; kiểm tra lại điều kiện quan trọng lúc claim trước gửi.
- [ ] Chặn client giả factory/direction; ghi snapshot config/time và quy tắc EXIT/SEC exception.

### Acceptance criteria
- [ ] AC1: Grant LA cho employee tổ chức BD được xử lý theo grant, không theo employee.site.
- [ ] AC2: Denied attempt không gửi OPEN hoặc tạo attendance.
- [ ] AC3: Client payload không ghi đè station/factory/direction phía server.

### Verification plan
- [ ] Unit tests grant đúng/sai factory, revoked, boundary validTo, station maintenance.
- [ ] API test station spoof và inactive employee.
- [ ] Test policy EXIT đã ghi trong ADR, không dùng demo auto-toggle direction.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/gate`, `api/src/modules/eqr`, `api/src/modules/cfg`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
