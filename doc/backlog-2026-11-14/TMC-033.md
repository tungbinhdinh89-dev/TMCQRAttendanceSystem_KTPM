## TMC-033 · Document SOLID evidence from implementation

**Type:** DOCS · **Feature:** architecture · **Priority:** P0 · **Area:** architecture

**Dependencies:** [TMC-019](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/19), [TMC-024](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/24), [TMC-085](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/89)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Ticket riêng cho SOLID Implementation Examples. Đánh giá code module đã có, chỉ refactor nhỏ khi có vi phạm cụ thể và bảo toàn behavior.

### Scope / Implementation checklist
- [ ] Map SRP cho validator/policy/dispatcher/writer; DIP cho use case/ports và bootstrap providers.
- [ ] Map OCP cho mock/HTTP adapter và ISP cho interface tách open/status/query.
- [ ] Chứng minh LSP qua contract tests, giữ UNKNOWN semantics giống nhau giữa adapter.
- [ ] Ghi file/symbol/commit, lợi ích và trade-off; sửa import/framework leakage nếu tìm thấy.

### Acceptance criteria
- [ ] AC1: Có ví dụ cụ thể cho S/O/L/I/D, link source và assertion/contract test.
- [ ] AC2: Không thêm interface/lớp trống chỉ để đủ danh sách SOLID.
- [ ] AC3: Refactor nếu có không làm thay đổi policy hoặc bỏ concurrency constraints.

### Verification plan
- [ ] Review import boundary và dùng cùng contract test cho adapters.
- [ ] Chạy suite bị ảnh hưởng bởi refactor.
- [ ] Kiểm tra link source theo commit và so code thật với mô tả.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules`, `api/test`, `report/sections/content.tex`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
