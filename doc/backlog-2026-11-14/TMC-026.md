## TMC-026 · Exercise lost responses and process crash scenarios

**Type:** TEST · **Feature:** reliability · **Priority:** P0 · **Area:** backend

**Parent:** [TMC-095](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/101)
**Dependencies:** [TMC-013](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/13), [TMC-016](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/16), [TMC-022](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/22)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Tạo harness điều khiển lỗi có thể lặp lại và quan sát cả app DB lẫn mock TCS. Không gọi test demo mode là bằng chứng môi trường sản xuất.

### Scope / Implementation checklist
- [ ] Thêm test hooks trước DB commit, sau claim commit, sau TCS execute và trước gửi response.
- [ ] Cho phép mô phỏng API↔DB, kiosk↔API và API↔TCS độc lập.
- [ ] Thu execution ledger mock, DB counts và correlationId để so sánh trước/sau restart.
- [ ] Khóa fault-control dưới env test/demo, không public hoặc luôn bật.

### Acceptance criteria
- [ ] AC1: Mỗi fault mode có trigger/expected state/cleanup tái lập được.
- [ ] AC2: Mất ACK sau OPEN có physical execution dù client timeout.
- [ ] AC3: Restart app không xóa ledger mock trong bài test nhằm che duplicate.

### Verification plan
- [ ] Smoke từng fault switch và reset môi trường test riêng.
- [ ] Kiểm tra disable fault hooks ở config ngoài demo/test.
- [ ] So log và DB snapshot không chứa secret/raw QR.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/gate`, `api/src/modules/rpt`, `client/src/features/access-control/Access.tsx`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
