## TMC-049 · Import verified ticket metadata without duplicate issues

**Type:** TASK · **Feature:** foundation · **Priority:** P0 · **Area:** devops

**Parent:** [TMC-101](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/107)
**Dependencies:** [TMC-046](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/50), [TMC-047](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/51), [TMC-048](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/52)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Chuẩn bị import batches theo dependency/milestone; tra issue/ID trước khi create/update/reuse; lưu mapping internal ID → issue → Project item sau từng batch được giao.

### Scope / Implementation checklist
- [ ] Chuẩn bị import batches theo dependency/milestone
- [ ] tra issue/ID trước khi create/update/reuse
- [ ] lưu mapping internal ID → issue → Project item sau từng batch được giao.

### Acceptance criteria
- [ ] AC1: Giữ toàn bộ ID/parent/type/Feature, milestone/dates đúng; legacy remote mapping chưa biết ghi Unverified.
- [ ] AC2: Retry phần chưa tạo, không nhân đôi; Ready chỉ khi DoR và user chọn, không từ việc import.

### Verification plan
- [ ] Dry-run bảng import trước mutation; so count/duplicates/parent và titles.
- [ ] Đối chiếu remote response/URL sau batch khi được phép, không fabricate issue numbers.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `doc/backlog.md`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
