## TMC-009 · Implement QR credential and signing-key metadata

**Type:** FEATURE · **Feature:** qr · **Priority:** P0 · **Area:** security

**Parent:** [TMC-091](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/97)
**Dependencies:** [TMC-004](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/4), [TMC-006](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/6)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Hiện thực model credential và key metadata theo schema; key material chỉ ở env/secret provider. Chưa tạo màn quản lý khóa đầy đủ.

### Scope / Implementation checklist
- [ ] Tạo QrCredential aggregate, repository, signing-key registry và mapper.
- [ ] Cấu hình kid, algorithm allowlist, public JWK và private secret reference.
- [ ] Seed một key hoạt động, một verify-only/revoked để test rotation.
- [ ] Thêm command cấp credential có actor HR/scope và audit trong UnitOfWork.

### Acceptance criteria
- [ ] AC1: Chỉ một credential ACTIVE cho mỗi employee theo policy/schema.
- [ ] AC2: Private key không nằm trong DB payload, client bundle hay logs.
- [ ] AC3: Key không biết hoặc REVOKED không được dùng xác minh token mới.

### Verification plan
- [ ] Unit test vòng đời credential và key status.
- [ ] Integration test partial unique active credential.
- [ ] Quét secret trong fixture/log và kiểm tra metadata không chứa private JWK parameters.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/eqr`, `contracts/src/employee.ts`, `api/src/modules/iam`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
