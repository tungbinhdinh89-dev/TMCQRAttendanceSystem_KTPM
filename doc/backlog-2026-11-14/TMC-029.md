## TMC-029 · Verify the main module against PostgreSQL

**Type:** TEST · **Feature:** verification · **Priority:** P0 · **Area:** backend

**Parent:** [TMC-102](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/108)
**Dependencies:** [TMC-019](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/19), [TMC-020](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/20), [TMC-015](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/15)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Củng cố unit/integration/API tests đã viết trong từng ticket; không đợi tới tuần 4 mới bắt đầu test. Đây là ticket chất lượng độc lập cho module chính.

### Scope / Implementation checklist
- [ ] Tạo matrix valid/invalid/expired/revoked QR, access grant và station policy.
- [ ] Chạy PG transaction/unique/deferred head tests và kiểm tra nguồn attendance.
- [ ] Chạy API tests auth/station/status/history theo contract.
- [ ] Lưu command, commit hash, môi trường, số test và kết quả thực tế; ghi failure còn lại.

### Acceptance criteria
- [ ] AC1: Happy path EMP QR→kiosk→mock passage→PG history tái lập được.
- [ ] AC2: Denied/ACK-only/UNKNOWN không tạo công; dữ liệu tồn tại sau restart.
- [ ] AC3: Test không dùng SQLite hoặc mock repository để tuyên bố PG constraints đúng.

### Verification plan
- [ ] Unit suite và PG integration suite trên DB sạch.
- [ ] API regression với các role đại diện.
- [ ] Review assertions về state, DB count, audit và mock execution counter.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/test`, `api/package.json`, `api/src/modules/gate`, `api/src/modules/att`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
