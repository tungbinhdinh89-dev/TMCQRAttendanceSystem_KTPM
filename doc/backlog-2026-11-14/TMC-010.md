## TMC-010 · Issue short-lived QR tokens and revoke credentials

**Type:** FEATURE · **Feature:** qr · **Priority:** P0 · **Area:** security

**Parent:** [TMC-091](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/97)
**Dependencies:** [TMC-009](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/9), [TMC-007](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/7)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Cấp token ký bất đối xứng với jti gắn qr_tokens.id. TTL 60 giây là cấu hình demo, không phải mức bắt buộc của đề.

### Scope / Implementation checklist
- [ ] Tạo GET/POST self QR endpoint theo OpenAPI, lấy employee từ session và quyền hiện hành.
- [ ] Ký token có kid/iss/aud/sub/jti/iat/exp theo contract, lưu token hash/expiry; không lưu raw payload.
- [ ] Tạo HR revoke credential endpoint có reason/audit; refresh tạo jti mới, không kéo dài mã cũ.
- [ ] Giới hạn tần suất cấp token và trả serverTime/expiresAt cho UI countdown.

### Acceptance criteria
- [ ] AC1: Client không phát hành token cho employeeId tùy ý.
- [ ] AC2: Token sinh từ credential revoked/inactive bị từ chối; thu hồi tác dụng ở lần check server sau.
- [ ] AC3: Refresh cho token mới có expiry hợp lệ và traceable, không ghi token vào log.

### Verification plan
- [ ] API self-only và HR scope/reason.
- [ ] Test expiry/refresh bằng clock giả, không chờ sleep.
- [ ] Test revoke rồi dùng token còn hạn và giới hạn request cấp mã.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/eqr`, `contracts/src/employee.ts`, `api/src/modules/iam`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
