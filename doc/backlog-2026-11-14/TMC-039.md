## TMC-039 · Monitor station heartbeat and pending work

**Type:** ENHANCEMENT · **Feature:** gate-config · **Priority:** P1 · **Area:** frontend

**Parent:** [TMC-092](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/98)
**Dependencies:** [TMC-028](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/28), [TMC-024](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/24)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
P1 hoãn sau M2 baseline. Mở rộng dashboard bằng heartbeat/authenticated station health và số liệu worker; không triển khai observability platform.

### Scope / Implementation checklist
- [ ] Thêm heartbeat endpoint từ trạm đã xác thực và lưu lastSeen.
- [ ] Định nghĩa stale threshold cấu hình, phân biệt station connectivity với TCS/device physical health.
- [ ] Tổng hợp pending/failed jobs, case age, UNKNOWN và latency từ dữ liệu thật.
- [ ] Hiển thị timestamp/chất lượng dữ liệu và factory-scoped metrics.

### Acceptance criteria
- [ ] AC1: Không đồng nhất heartbeat app với cổng vật lý hoạt động.
- [ ] AC2: Scope của metrics giống API nghiệp vụ.
- [ ] AC3: Backlog tăng có thể quan sát và stale heartbeat hiển thị UNKNOWN/OFFLINE rõ.

### Verification plan
- [ ] Fake clock cho stale threshold và trạm revoked.
- [ ] Cross-factory metrics và API rate limit.
- [ ] So counts với jobs/cases fixture.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `client/src/features/dashboard/Dashboard.tsx`, `api/src/modules/gate`, `api/src/modules/rpt`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
