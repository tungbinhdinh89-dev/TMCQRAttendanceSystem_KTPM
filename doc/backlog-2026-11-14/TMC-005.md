## TMC-005 · Complete Node test runners and CI contracts

**Type:** CI · **Feature:** foundation · **Priority:** P0 · **Area:** devops

**Parent:** [TMC-101](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/107)
**Dependencies:** [TMC-003](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/3), [TMC-004](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/4)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
Đã có Node test runner và thay đổi OpenAPI/CI trong workspace. Đối chiếu manifest/revision khi nhận ticket; bổ sung check còn thiếu, không ghi đè thay đổi chưa commit.

### Scope / Implementation checklist
- [ ] Tạo unit runner và integration runner dùng PostgreSQL test; thêm fixture/reset có kiểm soát.
- [ ] Thêm scripts typecheck, test, test:integration cho api và test:e2e cho client.
- [ ] Tạo CI install bằng lockfile, build hai app, migration/test với PG service và artifact kết quả.
- [ ] Xuất OpenAPI/contract check và ghi danh mục script ở README kỹ thuật.

### Acceptance criteria
- [ ] AC1: Một integration test thực sự kết nối PG và rollback fixture.
- [ ] AC2: CI/script fail khi assertion fail, không bỏ qua lỗi bằng catch hoặc continue-on-error.
- [ ] AC3: Không commit secrets và không chạy reset vào DB vận hành.

### Verification plan
- [ ] Chạy pipeline local tương ứng; tạo test fail tạm rồi khôi phục để kiểm tra exit code.
- [ ] Xác minh env test độc lập và migrations dùng đúng DB.
- [ ] Validate OpenAPI và health response.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/package.json`, `api/test`, `client/test`, `.github/workflows (proposed)`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
