## TMC-103 · Implement durable audit writes and scoped audit search

**Type:** FEATURE · **Feature:** audit · **Priority:** P0 · **Area:** security

**Parent:** [TMC-096](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/102)
**Dependencies:** [TMC-007](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/7), [TMC-004](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/4)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
AuditEntry mới có persistence; chưa có use case ghi/query audit cho thao tác nghiệp vụ.

### Scope / Implementation checklist
- [ ] Định nghĩa audit port và event schema actor/action/object/outcome/reason/correlationId; redact dữ liệu nhạy cảm.
- [ ] Ghi audit thay đổi dữ liệu cùng transaction; thất bại đăng nhập/từ chối quyền có đường ghi riêng phù hợp.
- [ ] Thêm query API có scope, filter/pagination và UI tra cứu tối thiểu; không cung cấp sửa/xóa audit qua UI.

### Acceptance criteria
- [ ] AC1: Tạo/sửa employee, revoke QR, đổi role/station, correction và export có audit truy vết theo operation đã triển khai.
- [ ] AC2: Rollback thay đổi nghiệp vụ không để audit thành công giả; lỗi audit bắt buộc không bị bỏ qua im lặng.
- [ ] AC3: EMP/EXE không đọc log ngoài quyền; log không chứa mật khẩu, raw session/QR, station secret hoặc private key.

### Verification plan
- [ ] Kiểm tra commit/rollback và audit ở DB test; correlationId nối request với attempt/command.
- [ ] Gọi trực tiếp query audit ngoài scope; kiểm tra redaction bằng payload chứa dữ liệu nhạy cảm.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/modules/iam`, `contracts/src`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
