## TMC-003 · Complete backend ports and shared wire contracts

**Type:** BUILD · **Feature:** foundation · **Priority:** P0 · **Area:** devops

**Parent:** [TMC-101](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/107)
**Dependencies:** [TMC-002](https://github.com/tungbinhdinh89/TMCQRAttendanceSystem_KTPM/issues/2)
**Assignee / estimate / target date:** Chưa phân công hoặc cam kết; người phụ trách cập nhật sau refinement.

### Problem / Outcome
NestJS và contracts đã có. Hoàn thiện wiring, application ports và DTO cho nghiệp vụ còn thiếu; không dựng lại scaffold.

### Scope / Implementation checklist
- [ ] Dựng Nest bootstrap, health endpoint và config validation không lộ secret.
- [ ] Định nghĩa Clock, IdGenerator, UnitOfWork/TransactionContext, QrValidator, TurnstileGateway, AttendanceWriter và AuditWriter.
- [ ] Định nghĩa DTO/error codes/correlationId; tách decision, commandState và attendanceState.
- [ ] Đăng ký provider ở composition root; thêm script build/typecheck/test và ghi API schema.

### Acceptance criteria
- [ ] AC1: Health endpoint chạy, core không import Nest/TypeORM/HTTP types.
- [ ] AC2: Use case nhận port qua constructor; không có singleton mutable transaction manager.
- [ ] AC3: Scan/lookup contract giữ eventId và mô tả 409 payload conflict.

### Verification plan
- [ ] Build/typecheck api.
- [ ] Unit smoke test khởi tạo use case với fake ports.
- [ ] Kiểm tra dependency/import của domain và application.
- [ ] Chọn lệnh check từ manifest tại revision thực hiện. Không truyền --runInBand cho Node test runner. Integration chỉ dùng môi trường DB test đã chỉ định; không reset/seed DB hiện tại.

### Deliverables
- PR/diff, contracts/migration khi có thay đổi và evidence gắn revision; đánh giá từng AC, lỗi và giới hạn.
- Module/file định hướng: `api/src/bootstrap/modules`, `api/src/platform/application`, `contracts/src`; kiểm tra đường dẫn thực tế khi nhận việc.

### Definition of Done
- [ ] Mọi AC trong scope có evidence thật; build/typecheck/tests phù hợp phần thay đổi đạt; UI có visual check nếu áp dụng.
- [ ] Thay đổi đúng bounded context; contracts không phụ thuộc framework/ORM; thay schema có migration/constraint plan, không synchronize.
- [ ] PR được người dùng review/nghiệm thu; không tự merge/approve hoặc đánh dấu Done.
- [ ] Cập nhật tài liệu và giới hạn; simulator không chứng minh tích hợp thiết bị/HRS thật.
